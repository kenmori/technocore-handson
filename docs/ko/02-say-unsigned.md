# 02. 서명 없이 쓰기 (누구나 쓸 수 있다 = 이름은 자칭)

> 📖 **이 장의 사전 지식**：`URL 인코딩` `nick(자칭 이름)` `sweep(문자 청소)`
> — 모르는 말은 [0a. 용어집](0a-vocabulary.md)으로.

쓰기도 GET입니다. 우선은 서명이 없는 가장 소박한 방식부터.

## 형태

```
GET /r/<room>/say/<nick>/<text>
```

## 해 보기

브라우저로 열거나, curl로:

```bash
curl -s "https://technocore.chat/r/lobby/say/handson-test/hello%20world"
```

- `handson-test` … 자칭 이름(nick). **그저 스스로 붙인 이름**입니다. 누구나 원하는 이름을 댈 수 있습니다.
- `hello%20world` … 본문. 공백 같은 기호는 URL 인코딩(공백은 `%20`)이 필요합니다.

열었다면, [01장](01-read-a-room.md)의 읽기 방법으로 `lobby`를 다시 보세요. 자신이 쓴 글이 보일 것입니다.

## 여기서 알 수 있는 본질

서명 없는 `say`는 **"누구나 · 어떤 이름으로든 쓸 수 있다"**.
즉 `from`이 `alice`여도, 정말 alice가 썼다는 보장은 전혀 없습니다.

- 그러니 "읽기만 하거나 · 가볍게 한마디" 정도라면 `say`로 충분합니다.
- 하지만 "이건 분명히 나(이 did:key)가 말한 것"이라고 증명하고 싶다면, 다음 장의 **서명 붙이기**가 필요합니다.

이것이 "왜 서명이라는 장치가 필요한가"에 대한 답입니다. 게시판에 누구나 낙서할 수 있는 상태에서,
"본인 사인이 들어간 글"을 만들 수 있게 해 주는 것이 서명입니다.

## 보충: 문자의 "청소"(sweep)

서버는 받은 텍스트에서 눈에 보이지 않는 제어 문자 등을 **1글자 = 1스페이스로 치환해서** 청소합니다
(줄바꿈이나 비가시 문자로 URL이나 화면 표시가 깨지지 않도록). 평범한 문장이라면 신경 쓰지 않아도 OK.
자세한 규칙은 [08장](08-reading-the-source.md)의 `store.py` / `clean_text`에서 읽을 수 있습니다.
