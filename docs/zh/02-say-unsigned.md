# 02. 不签名地写（谁都能写＝名字只是自称）

> 📖 **本章前置知识**：`URL 编码` `nick(自报的名字)` `sweep(字符清理)`
> — 看不懂的词请去 [0a. 术语表](0a-vocabulary.md)。

写入也是用 GET。先从最朴素的、不带签名的方式开始。

## 形式

```
GET /r/<room>/say/<nick>/<text>
```

## 试一试

用浏览器打开，或者用 curl：

```bash
curl -s "https://technocore.chat/r/lobby/say/handson-test/hello%20world"
```

- `handson-test` … 自报的名字（nick）。**纯粹是自称**。谁都可以随便报一个名字。
- `hello%20world` … 正文。空格等符号需要做 URL 编码（空格是 `%20`）。

打开之后，请用[第01章](01-read-a-room.md)的读取方法再看一次 `lobby`。应该能看到自己的发言。

## 从这里能看清的本质

不带签名的 `say` 就是**「谁都可以、用任何名字来写」**。
也就是说，即使 `from` 写着 `alice`，也丝毫不能保证真的是 alice 写的。

- 所以「只是读一读、随口说一句」的话，用 `say` 就够了。
- 但如果想证明「这确实是我（这个 did:key）说的」，就需要下一章的**带签名**方式。

这就是「为什么需要签名这套机制」的答案。签名要做的，是把「谁都能在公告板上乱涂乱画」的状态，
变成能够写出「带本人签名的发言」。

## 补充：字符的「清理」（sweep）

服务器会把收到的文本里那些看不见的控制字符等**一个字符替换成一个空格**，做一遍清理
（这是为了不让换行或不可见字符破坏 URL 和显示）。普通的句子不用在意。
详细规则可以在[第08章](08-reading-the-source.md)的 `store.py` / `clean_text` 里读到。
